TUNEWRAP WEB — STAGE 12.2: PRICING CMS

Цель:
сделать экран «Стоимость и форматы» таким же управляемым из Admin Studio,
как музыка и заказы.

После Stage 12.2 для изменения цены/названия/описания НЕ НУЖНЫ:
- GitHub;
- редактирование кода;
- новая сборка сайта.

Меняем в /admin/pricing.html → Сохранить → D1 → публичный сайт читает новые данные.

ЧТО МОЖНО РЕДАКТИРОВАТЬ

Страница:
- «Стоимость и форматы»
- «Выберите свой формат»
- подзаголовок
- текст акции
- срок акции
- «Свадебный формат»
- свадебный подзаголовок
- «Подробнее»
- подписи внутри detail-card
- доплата за срочность
- валюта

- показывать / скрыть
- порядок
- название
- старая цена
- новая цена
- бейдж
- весь список «Что входит»

Свадебные:
- показывать / скрыть
- порядок
- название
- старая цена
- новая цена
- короткий текст
- полное описание

- «Идеально подходит для»
- текст кнопки

ЯЗЫКИ
RU / UA / GE / EN / DE.
Цена общая.
Текст каждого языка хранится отдельно.
Есть кнопка «Автоперевести язык», использующая уже существующий TuneWrap Workers AI translation API.

ВАЖНО
Технические ID пакетов остаются стабильными:
simple / advanced / hit
first-dance / love-story / wedding-collection

Поэтому можно переименовать «Просто» хоть в «Старт»,
а First Dance — в другое видимое название: заказы не ломаются.

АРХИТЕКТУРА
D1:
pricing_config — одна версионируемая JSON-конфигурация.

API:
GET  /api/pricing
GET  /api/admin/pricing
PUT  /api/admin/pricing

Admin API защищён существующим Cloudflare Access JWT.
PUT также проверяет same-origin.

Публичный runtime накладывает D1-данные поверх проверенного старого Pricing.
Если Pricing API когда-либо временно недоступен, сайт остаётся со встроенными ценами/текстом, а музыка не ломается.

ЗАКАЗЫ
Pricing CMS загружается ДО Orders CRM.
Поэтому в новую заявку сохраняется цена из CMS, включая изменённую стоимость и срочную доплату.

УСТАНОВКА

1. Распаковать ZIP поверх корня website.

2. Добавить вкладку «Стоимость» в существующие Music / Orders Admin:
   node scripts/install-pricing-admin-nav.js

3. D1:
   Cloudflare Dashboard → D1 → tunewrap-catalog → Console.
   Открыть migrations/0004_pricing_cms.sql, скопировать весь SQL и Execute.

4. Проверка:
   npm.cmd test
   npx.cmd wrangler pages functions build

5. GitHub Desktop:
   Summary:
   Stage 12.2 – Pricing CMS

   Commit to main → Push origin.

6. После зелёного Cloudflare:
   /admin/pricing.html

ПЕРВАЯ ПРОВЕРКА
- изменить $19 временно на $20;
- Сохранить;
- открыть публичный сайт Ctrl+F5;
- убедиться, что карточка и detail-card показывают $20;
- вернуть $19;
- Сохранить.

После этой проверки управление ценами больше не требует деплоя.

ПРИМЕЧАНИЕ ПО ПЕРЕВОДАМ
Миграция специально переносит в D1 RU как исходный управляемый контент.
Пока конкретный другой язык не заполнен в CMS, сайт сохраняет свой существующий встроенный перевод.
Это исключает регрессию при установке.
