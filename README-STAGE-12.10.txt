TUNEWRAP WEB — STAGE 12.10
PRICING / GIFT / PACKAGE UX POLISH

Что меняется

1. ОТКРЫТЫЕ КАРТОЧКИ ТАРИФОВ
Все 6 пакетов используют одну компактную систему:
- Просто
- Продвинутый
- Хит
- First Dance
- Love Story
- Wedding Collection

Свадебная карточка больше не разворачивается в длинный экран с большой картинкой,
описанием, вложенными блоками «Что входит» / «Идеально подходит».

Для свадебных пакетов показываются:
- СВАДЕБНЫЙ ФОРМАТ
- название
- старая цена
- новая цена
- акция
- 4 основных пункта
- одна золотая кнопка

То есть по размеру и логике это та же карточка, что «Просто».

2. КРЕСТИК НА КАРТОЧКЕ
Существующий #tierDetailClose НЕ дублируется.
Он физически переносится внутрь открытой карточки вправо сверху.

Desktop / tablet:
  × Закрыть

Phone:
  круглый ×

Старый крестик слева сверху экрана исчезает, потому что тот же самый DOM button
теперь находится внутри карточки. Поведение закрытия остаётся у существующего core.

3. ПОДАРОЧНЫЙ СЕРТИФИКАТ
Desktop / tablet:
  3 обычных карточки одной строкой
  3 свадебных карточки второй строкой

Phone:
  3 компактные полноширинные карточки «Песни»
  3 компактные полноширинные карточки «Свадебные форматы»

Больше нет визуального 2 + 1 / пустого места.

4. ВЫБОР ПАКЕТА В АНКЕТЕ
Системный Android / browser <select> больше не виден пользователю.

Вместо него:
- фирменная кнопка TuneWrap в форме;
- собственное всплывающее окно;
- «Песни» — 3 красивых package buttons;
- «Свадебные форматы» — 3 красивых package buttons;
- название слева;
- старая / новая цена справа;
- выбранный пакет получает золотую рамку + ✓;
- крестик справа сверху;
- backdrop также закрывает окно;
- Escape закрывает на desktop;
- если человек просто смотрит форму, он может закрыть окно, ничего не выбирая.

ВАЖНО:
старый #fieldTier остаётся в DOM скрытым как compatibility/data owner.
Новый UI при выборе выставляет его value и вызывает его СУЩЕСТВУЮЩИЙ change handler.
То есть мы НЕ создаём вторую бизнес-логику выбора тарифа.

5. ИСТОЧНИК ДАННЫХ
Названия / цены / oldPrice / enabled берутся из существующего Pricing CMS:
window.__tuneWrapPricing.config / window.TUNEWRAP_PRICING_CMS

Меняем цену в Admin Pricing → она меняется во всех новых элементах.

НЕ МЕНЯЕТСЯ:
- Orders API
- D1
- Pricing CMS
- package IDs
- Certificate CRM flow
- Player
- Music catalog
- Queue
- Admin

D1 migration НЕ НУЖНА.

Установка

1. Распаковать ZIP поверх website.
2. Запустить:
   node scripts/install-stage-12.10-package-ui-polish.js
3. Затем:
   node scripts/stage-12.10-package-ui-test.js
   npm.cmd test
   npx.cmd wrangler pages functions build
4. Restore _worker.bundle.
5. GitHub Desktop Summary:
   Stage 12.10 – Package UI Polish
6. Commit to main → Push origin.

Проверка после деплоя

PHONE
A. Пакеты:
- открыть «Просто» → X справа внутри карточки;
- открыть First Dance → карточка такого же формата/масштаба, X справа;
- открыть Love Story / Wedding Collection.

B. Сертификат:
- 3 обычных пакета аккуратно друг под другом;
- 3 свадебных аккуратно друг под другом;
- ничего не «висит» одинокой карточкой.

C. Анкета:
- нажать «Пакет и стоимость»;
- вместо Android select открывается фирменное окно;
- закрыть X, ничего не выбирая;
- открыть снова;
- выбрать First Dance;
- цена/пакет должны попасть в существующую форму.

TABLET / DESKTOP
- сертификат = ровно 3 + 3;
- chooser = 3 + 3;
- закрытие detail card справа сверху;
- hover/focus состояния работают.
