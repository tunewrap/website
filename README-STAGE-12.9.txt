TUNEWRAP WEB — STAGE 12.9
MUSIC CURATION ADMIN

Что добавлено

Admin → Музыка → «Порядок и витрина»

Новая страница:
  /admin/curation.html

1. ПОРЯДОК — MUSICAL STORIES
Можно:
- перетаскивать треки мышкой;
- двигать ↑ / ↓;
- сохранить новый порядок одной кнопкой.

Порядок использует уже существующий sort_order.
После сохранения он влияет на:
- библиотеку «Музыкальные истории»;
- порядок Stories в глобальной очереди;
- порядок опубликованных песен в каталоге.

Черновики тоже видны в сортировке.
Их можно заранее поставить в нужное место — после публикации они появятся именно там.

2. ПОРЯДОК — AUTHOR
Полностью отдельная сортировка.
Она влияет на:
- авторскую библиотеку;
- вторую часть глобальной очереди после Stories.

Stories и Author друг друга не перемешивают.

3. ГЛАВНАЯ ПЕСНЯ STORIES
На странице есть отдельный блок:
«Главная песня на основном экране».

В выпадающем списке доступны все опубликованные Stories.
Выбираешь трек → «Поставить на витрину».

Например:
- Аліна;
- Ночь и слова;
- любой другой опубликованный трек.

4. ГЛАВНАЯ ПЕСНЯ AUTHOR
Такой же отдельный выбор для Author.

Например можно поставить:
- Intro TuneWrap;
- Tbilisi;
- любой другой опубликованный авторский трек.

5. ВАЖНАЯ АРХИТЕКТУРА
Новая таблица D1 НЕ нужна.

У TuneWrap уже существуют:
- tracks.sort_order;
- tracks.featured;
- POST /api/admin/reorder;
- PATCH /api/admin/tracks/:id.

При выборе featured=true существующий API автоматически снимает featured
со всех остальных треков этого же раздела.
То есть в Stories одна главная песня, и в Author одна главная песня.

Public Catalog уже читает featured отдельно для:
- stories;
- author.

Поэтому изменение из Admin начинает работать на публичном сайте
без Git commit / rebuild после этой Stage.

6. В РЕДАКТОРЕ ТРЕКА
Старое техническое название:
  Featured в разделе
переименовано в понятное:
  Главная песня раздела

7. ЧТО НЕ ТРОГАЕТСЯ
- D1 schema;
- MP3 / R2;
- Player;
- Queue engine;
- Categories;
- Pricing;
- Orders;
- Site CMS;
- Gift Certificate.

D1 MIGRATION НЕ НУЖНА.

Установка

1. Распаковать ZIP поверх website.
2. Выполнить:
   node scripts/install-stage-12.9-music-curation.js
3. Тест Stage:
   node scripts/music-curation-admin-test.js
4. Общий тест:
   npm.cmd test
5. Build:
   npx.cmd wrangler pages functions build
6. Restore _worker.bundle.
7. GitHub Desktop Summary:
   Stage 12.9 – Music Curation Admin
8. Commit to main → Push origin.

Production test

A. Открыть:
   /admin/

B. Нажать:
   «Порядок и витрина»

C. Stories:
   переставить два трека → Сохранить порядок.
   Открыть публичную библиотеку Stories и проверить порядок.

D. Author:
   переставить два трека → Сохранить порядок.
   Проверить авторскую библиотеку.

E. В «Витрина Stories» выбрать любой опубликованный трек.
   На основном экране Musical Stories должна измениться главная песня.

F. В «Витрина Author» выбрать, например, Intro TuneWrap.
   На основном экране Author должна измениться главная песня.

После Stage 12.9 дальнейшая перестановка и смена главных треков делаются
только через Admin Studio — без изменения кода.
